# 跨领域知识体系（Knowledge Framework）

> 一个**与领域无关**的七维 facet 骨架 + 一套**确定性**的覆盖度评估，把"任意一个领域 / 概念 / 定理 / 范式"
> 变成可推敲、闭环、严谨、可评估、可解释、可演进的知识地图。
> 目标不是罗列要点，而是让人（尤其跨领域的人）据此**建立能继续推理的模型**：背景是什么、要解决什么问题、
> 方案如何演进、核心机制与边界、如何评估、怎么落地、如何演进。

相关：[`service.md`](service.md)（`mode=knowledge` 的 HTTP 用法）、[`deep-research.md`](deep-research.md)
（底层引擎）、skill 源文件 [`skills/knowledge-framework/SKILL.md`](../skills/knowledge-framework/SKILL.md)。

代码：`src/research_bot/knowledge.py`（`FACETS` / `build_knowledge_topic` / `evaluate_coverage`）。

---

## 1. 为什么是"固定骨架"

零散要点无法横向比较，也无法增量演进。固定七个 facet 后：**任意两个领域的知识地图结构同构**，可逐维对照；
新知识只需补进既有槽位，不需重构。这是"可演进而非重写"的前提。

| # | facet | 必须回答 |
| --- | --- | --- |
| 1 | 定位与背景 Positioning | 定义（what it **is** / **is NOT**）、它为何存在、依赖哪些**前置知识体系** |
| 2 | 问题域 Problem Space | 核心问题、问题的形式化表述、关键约束与不变量 |
| 3 | 历史与演进 Evolution | 时间线/代际；**每一代解决了什么、又新引入了什么**（代价闭环） |
| 4 | 核心机制 Mechanism | 概念/原理/定理/范式、关键**权衡**、**作用域**（何时适用/何时不适用、反例） |
| 5 | 证据与评估 Evaluation | 指标/基准/可复现性、可解释性、**反例与失败模式**、争议 |
| 6 | 实践与生态 Practice | 经典工作与人物、工具与库、落地案例、**学习路径**（前置顺序） |
| 7 | 关联与元层 Meta | 相邻领域关系与边界、该领域知识**如何被验证/推翻**、开放问题与演进方向 |

## 2. 严谨性不变量（skill 与评估器共同强制）

1. **可溯源**：每条论断带 `[n]`；取不到写 `> 待核实`，**不得编造**。
2. **有边界**：每个机制/结论必须给出**适用边界或反例**——说不清"何时不适用"的机制等于没讲清。
3. **闭环**：每个"解决了 X"必须配"新引入了代价/问题 Y"。
4. **可评估**：论断尽量挂到**可测指标/基准/证明标准**上。
5. **可解释可学**：术语表 + **前置知识依赖** + 学习路径，让外行能按序学下去。
6. **可演进**：结构固定，后续知识直接补槽。

这些不变量不是口号：`skills/knowledge-framework/SKILL.md` 注入每次 LLM 调用，`evaluate_coverage()` 再**确定性**地核对。

## 3. 覆盖度评估（确定性，无需 LLM）

`evaluate_coverage(result) -> CoverageReport`：按报告标题切段 → 映射到七个 facet → 统计每段的
`claim_count`/`sourced`/`has_boundary`，再汇总：

```
score = 100 · ( 0.55·已覆盖facet比例 + 0.30·引用率 + 0.15·声明边界/代价的比例 )
```

- `populated`：该 facet 有实质内容（有 claim 行，或正文 ≥40 字符）。
- `has_boundary`：命中"边界/不适用/反例/局限/代价/权衡/新问题/仅当…"等标记。
- `gaps`：未覆盖的 facet、有内容但无引用的 facet、整体引用率偏低——**报缺口而不是静默接受**。

所以 `mode=knowledge` 的返回里带 `coverage`；CLI 用 `rb run --knowledge` 会打印 score 与 gaps。

## 4. 三个 worked examples

下面把同一骨架套到三个**完全不同**的领域，演示通用性。内容仅示范结构（真实报告由引擎检索生成并带 `[n]`）。

### 4.1 C++ **RAII**（一个语言惯用法）

| facet | 内容 |
| --- | --- |
| 定位与背景 | **是**：资源获取即初始化——把资源的生命周期绑定到对象生命周期。**不是**：不是 GC，也不是"手动 new/delete 的封装"。前置：构造函数/析构函数、栈对象、作用域、移动语义。 |
| 问题域 | 手工管理资源（内存、文件、锁、socket）易泄漏/双重释放/异常路径遗漏。形式化：在控制流含异常时，保证"获取-释放"成对且在最内层作用域退出时发生。不变量：**已获取 ⇒ 必释放**。 |
| 历史与演进 | 第1代：手动 new/delete——代价：异常不安全。第2代：RAII 对象（`std::vector`/`lock_guard`）——代价：需依赖栈展开，动不了需要转移所有权的场景。第3代：移动语义（C++11）——代价：需理解右值/`noexcept` 才安全。 |
| 核心机制 | 构造获取、析构释放，借**栈展开**保证异常路径也执行析构。权衡：把"释放时机"交给作用域而非程序员。**边界**：对非栈展开控制流（如 `longjmp`、析构中抛异常、跨 DLL 边界 ABI）不保证/危险；无 RAII 的裸句柄仍会泄漏。 |
| 证据与评估 | 可测：ASan/Valgrind 泄漏率、异常安全等级（basic/strong/nothrow）。**失败模式**：析构函数抛异常、循环引用（`shared_ptr`）、过早销毁被别处引用。 |
| 实践与生态 | 经典：`std::unique_ptr`/`shared_ptr`/`lock_guard`/`std::fstream`。**学习路径**：作用域 → 构造/析构 → 异常安全 → RAII → 移动语义 → 智能指针。 |
| 关联与元层 | 与 GC（自动但时机不定）相对；与 Rust 所有权（编译期检查 vs C++ 运行时约定）对照。开放问题：析构中抛异常的处理、`noexcept` 传播。 |

### 4.2 数学分析 **中值定理**（一个定理族）

| facet | 内容 |
| --- | --- |
| 定位与背景 | **是**：在连续/可微条件下，函数在区间内的平均（或瞬时）变化率必然在某点取到的定理族（Rolle / Lagrange / Cauchy / 积分中值）。**不是**：不是计算方法，而是存在性结论。前置：极限、连续、可导、闭区间最值定理。 |
| 问题域 | 如何在**不求出具体点**的前提下，由端点/整体信息推出区间内某点的导数性质。形式化：给定 `f` 在 `[a,b]` 连续、`(a,b)` 可导，∃`c` 使 `f'(c)=(f(b)-f(a))/(b-a)`。不变量：条件缺一不可。 |
| 历史与演进 | 第1代：Rolle 定理（等端点）——代价：要求两端相等，过强。第2代：Lagrange 中值定理（差商）——代价：只对单函数；两函数之比无结论。第3代：Cauchy 中值定理（双函数）——代价：需 `g'≠0`；进一步推广（Taylor、积分型）——代价：光滑性要求提高。 |
| 核心机制 | 化为 Rolle：构造辅助函数 `h(x)=f(x)-线性插值`，用闭区间最值 + Fermat 引理得驻点。**边界**：区间不闭/不可导/不连续时结论失效（反例：`|x|` 在含 0 区间；`1/x` 跨 0）。 |
| 证据与评估 | 可评估：定理前提逐条核验；反例集构造；用于证明的"严格性"（ε-δ/测度意义下的取等）。**失败模式**：把"存在 c"误用成"对某给定 c 成立"。 |
| 实践与生态 | 经典：Rolle/Lagrange/Cauchy/Taylor 余项、L'Hôpital 法则的证明基础。**学习路径**：极限 → 连续 → 可导 → Rolle → MVT → Cauchy/Taylor。 |
| 关联与元层 | 与拓扑的 Borsuk–Ulam、凸分析次梯度形式的相关性；多元/向量版（Hadamard）边界。开放问题：非光滑与随机意义下的类比。 |

### 4.3 具身智能 **real2sim / sim2real 世界模型**（一个范式）

| facet | 内容 |
| --- | --- |
| 定位与背景 | **是**：围绕"世界模型"在仿真与真实间迁移的一整套建模范式——real2sim（把真实资产/动力学搬进仿真）与 sim2real（把仿真学到的策略/模型迁移回真实）。**不是**：不是单一算法，而是覆盖**状态/传感器/行动/规划/决策**的建模闭环。前置：机器人动力学、感知、强化学习、系统辨识、图形学/渲染。 |
| 问题域 | 真实数据贵、危险、长尾难覆盖；仿真便宜但存在 **reality gap**。形式化：寻找映射使在 sim 上优化的策略在 real 上仍满足任务指标，且对未建模扰动鲁棒。不变量：sim 与 real 在**任务相关维度**上统计一致。 |
| 历史与演进 | 第1代：domain randomization 覆盖 gap——代价：需巨大随机化空间，样本效率低。第2代：system identification / real2sim 标定——代价：拟合的是特定工况，泛化弱。第3代：可微分仿真 + 神经世界模型（latent dynamics）——代价：可微近似误差、长时域漂移。第4代：真实数据微调 / 世界模型闭环——代价：真机数据与安全约束。 |
| 核心机制 | 按能力分层建模：**状态**（latent vs 物理量）、**传感器**（渲染/噪声模型）、**行动**（动作空间与延迟）、**规划**（MPC/扩散/搜索）、**决策**（RL/IL/规划器）。权衡：物理保真 ↔ 可微/可扩展。**边界**：接触密集、柔性体、新材质/新传感器下 gap 大；仿真里成立的最优策略可能不可迁移。 |
| 证据与评估 | 指标：sim-real 迁移成功率、Sim2Real gap、真机样本效率、鲁棒性（扰动/域移）、长时域漂移。**可复现性**：基准（manipulation/locomotion 任务族）、真机协议。**失败模式**：过拟合仿真纹理、误差累积致规划失稳、传感器模型失真。争议：纯仿真能否闭环到通用操作。 |
| 实践与生态 | 经典：域随机化、Isaac/MuJoCo 系、可微仿真、神经世界模型（latent dynamics / video world models）。**学习路径**：动力学 → 感知/渲染 → RL/IL → 域随机化/系统辨识 → 世界模型与可微仿真 → 真机部署。 |
| 关联与元层 | 与因果/迁移学习、控制理论（鲁棒/自适应）交界；如何被验证：真机复现与基准。开放问题：统一的状态-传感器-行动建模、长时域一致世界模型、安全探索。 |

> 三个例子共享同一张表——这正是"跨领域"的含义：**换领域不换骨架**。

## 5. 怎么用

```bash
# CLI：直接跑知识地图（打印 score + gaps）
rb run --knowledge --query "C++ RAII 的核心思想与边界" --depth quick
rb run --knowledge --query "数学分析中值定理族" --depth quick

# HTTP：mode=knowledge，轮询结果里带 coverage
curl -s -XPOST localhost:8080/research -H 'content-type: application/json' \
  -d '{"query":"real2sim / sim2real 世界模型建模思路","mode":"knowledge","depth":"quick"}'
```

新增领域无需写 YAML：`mode=knowledge` 会用 `<query> + 每维 probe` 作为种子检索式驱动 planner，
`sections` 即七个 facet，`knowledge-framework` skill 强制结构与纪律。
