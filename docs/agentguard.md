# AgentGuard：LLM 护栏与 Agent 安全

> 预研 + 规划 + 个人实践。目标不是"再做一个内容审核"，而是回答一个更难的问题：
> **当一个 LLM 能调用工具、读写文件、发请求、操作机器人时，凭什么允许它这么做，又怎么证明它没被带偏？**
>
> 配套话题：[`topics/agentguard.yaml`](../topics/agentguard.yaml)（`rb run --topic agentguard`）；
> 已接入每日增量 watch。相关：[`docs/knowledge-framework.md`](knowledge-framework.md)、
> [`docs/research-maintenance.md`](research-maintenance.md)、
> [`docs/intelligence_governance_final_report.md`](intelligence_governance_final_report.md)。

---

## 1. 定位与边界

**AgentGuard = 面向"有行动能力的 LLM"的护栏体系**，覆盖三件事：

1. **不被带偏**（提示注入 / 越狱 / 上下文污染）；
2. **不乱用权限**（工具滥用 / 过度代理 / 越权 / 数据外泄）；
3. **出错可收敛**（可观测、可拦截、可回滚、人在回路）。

**它不是什么**：
- 不等于内容审核（内容审核只处理"说什么"，AgentGuard 还要处理"做了什么"）；
- 不等于模型对齐（对齐是训练期属性，护栏是**运行时**的最后一道闸）；
- 不等于传统 AppSec（攻击面多了"自然语言即代码"这一维）。

一句话区分三者：**对齐管"想不想"，校准管"有多确定"，护栏管"能不能做"**。

## 2. 预研：威胁模型分层

把 Agent 的执行链拆成 6 层，每层有独立的攻击面与独立防线——这是整个领域最实用的心智模型：

| 层 | 攻击面 | 典型手法 | 对应防线 |
| --- | --- | --- | --- |
| L0 输入 | 用户/外部数据 | 直接越狱、编码绕过、多轮诱导 | 输入分类器、拒答策略、速率限制 |
| L1 模型 | 权重与解码 | 对抗后缀、越狱模板、微调投毒 | 对齐训练、安全微调、解码约束 |
| L2 上下文 | 检索/记忆/网页 | **间接提示注入**（网页、Issue、邮件、文档） | 来源隔离、内容消毒、指令/数据分离 |
| L3 工具 | 函数调用/MCP | 工具参数注入、工具描述投毒、MCP 服务端伪造 | 工具白名单、参数 schema 校验、服务端签名 |
| L4 权限 | 凭据与作用域 | 过度代理、权限提升、横向移动 | 最小权限、短时凭据、沙箱、审批 |
| L5 环境 | 真实世界与数据 | 数据外泄、不可逆操作、供应链 | 出站过滤、DLP、幂等/回滚、人在回路 |

**关键认知（预研结论）**：

- **间接提示注入是 Agent 时代的主战场**。直接注入靠"用户自己作恶"限制了危害；间接注入是"你信任的网页/Issue/邮件里藏了一句话"，攻击者不需要接触用户。这条线的奠基工作是 *Not What You've Signed Up For*，评测环境是 AgentDojo / InjecAgent。
- **"过度代理"（Excessive Agency）是工程落地的主要风险**，比越狱更现实：不是模型被骗，而是权限本来就给多了。OWASP LLM Top 10 把它单列一条。
- **评测严重滞后于产品**。文本越狱有 JailbreakBench / HarmBench，但"多步工具链 + 真实环境"的评测才刚起步（AgentDojo / AgentHarm）。**这是可发论文、可做产品的空白区**。
- **护栏的成本模型被忽视**：几乎所有论文只报 ASR（攻击成功率），很少报 **误杀率（FPR）与延迟**；而生产环境里，一个把正常请求拦掉的护栏会直接被下线。**"可用性"是真实护城河**。
- **MCP 让攻击面从"应用内"变成"生态级"**：第三方工具描述、服务端实现、工具返回内容都成了不可信输入。这是近两年新增的、标准尚未收敛的领域。

## 3. 规划：三层路线

### 3.1 能力分层（做哪一层）

| 层 | 门槛 | 竞争 | 建议 |
| --- | --- | --- | --- |
| 输入/输出分类器 | 低（微调一个模型即可） | 极卷 | ❌ 不做通用版 |
| 护栏编排框架 | 中 | 已有 Guardrails AI / NeMo / LLM Guard | ⚠️ 只做插件 |
| **运行时策略与最小权限** | 中高 | **相对空** | ✅ 主攻 |
| **Agent 安全评测（可执行环境）** | 高 | 空白 | ✅ 主攻 |
| **具身 Agent 的物理安全边界** | 很高 | **几乎无人** | ✅ 差异化王牌 |

### 3.2 时间规划

**第 1 阶段（1–2 个月）：建立可度量基线**
- 搭一个最小威胁模型：L2 间接注入 + L4 过度代理（这两条最现实）。
- 复现 2 个基准（AgentDojo、InjecAgent）的 baseline；把结果**连同 FPR 与 P95 延迟**一起记录。
- 产出：一份"护栏基线报告"——不做新产品，只做**可信测量**。测量本身就有价值。

**第 2 阶段（3–6 个月）：做一个可插拔的运行时护栏**
- 组件：工具白名单 + 参数 schema 校验 + 出站 DLP + 高风险动作审批 + 审计日志。
- 差异化：**策略即代码**（声明式策略而不是写死在 prompt 里），以及**可回滚的动作**（先 dry-run 再执行）。
- 产出：开源库 + 一套策略 DSL + 基准复现脚本。

**第 3 阶段（6–12 个月）：押注差异化——具身 Agent 护栏**
- 见 §4.1。这是你 C++/ROS2/具身背景能形成**别人抄不动**的护城河的方向。

### 3.3 度量口径（从第一天就固定）

| 指标 | 含义 | 为什么要 |
| --- | --- | --- |
| ASR | 攻击成功率 | 领域通用，便于对比 |
| **FPR** | 正常请求被误拦比例 | 决定能不能上线 |
| **P95 延迟** | 每次拦截的额外耗时 | 决定体验 |
| 覆盖率 | 工具/动作被策略覆盖的比例 | 决定盲区 |
| 可回滚率 | 不可逆操作占比 | 决定事故上限 |

> 一个只报 ASR 的护栏项目没有说服力；**同时报 ASR / FPR / 延迟**的，才像工程而不像 demo。

## 4. 实践：个人怎么做出亮点

按"差异化 × 可验证 × 可积累"排序，推荐 4 个候选，**建议主攻 4.1**，其余作为备选或组合。

### 4.1 ★ 主攻：具身 Agent 的运行时安全边界（Embodied AgentGuard）

**问题**：LLM 规划器 + 机器人执行器的组合，护栏不能只拦"文本"，还要拦"动作"。现有文本护栏对"往人所在的区域移动"完全无效。

**MVP（4–6 周）**
1. 一个仿真环境（MuJoCo / Isaac 或 ROS2 + Gazebo），LLM 输出动作序列；
2. 一层**动作级护栏**：速度/力矩/工作空间/人机距离的硬约束（安全包络），与 LLM 输出解耦、**在控制层强制执行**；
3. 一个**"注入即动作"攻击集**：在环境描述/物体标签/任务文档里埋指令，测试规划器是否被诱导执行危险动作；
4. 度量：危险动作拦截率、误拦率（正常任务成功率下降）、控制回路延迟。

**为什么是亮点**
- 文本护栏已经卷成红海，**"动作级护栏"几乎没人做**；
- 你有 C++/ROS2/运动学背景，**安全包络与实时控制**是你的天然优势；
- 与 `docs/intelligence_governance_final_report.md` 的 World→Value→Decision→Governance 闭环直接对接——它就是**闭环的最后一公里**；
- 可发表（安全/机器人交叉会议），也可产品化（工业机器人的 LLM 接口）。

**护城河**：失败案例库 + 专家标注的危险动作集 + 真机实验记录。这三样别人短期抄不到。

### 4.2 备选：间接注入的"来源消歧"中间件

**洞察**：间接注入的本质是**指令与数据混在同一通道**。做一个中间件，给每个上下文片段打"可信级别"标签（用户输入 / 系统策略 / 检索内容 / 工具返回），并在送入模型前做**结构化隔离**（不是简单加"忽略以下指令"这种无效 defense）。

**MVP**：一个 OpenAI 兼容的代理层，对检索内容做 span 级标记与消毒，复现 AgentDojo 上"有/无中间件"的 ASR 与 FPR 对比。

**亮点**：可作为任何 Agent 框架的 drop-in 组件；容易开源传播。

### 4.3 备选：护栏成本基准（Guardrail Bench）

**洞察**：业界缺一个**同时测 ASR / FPR / 延迟 / 成本**的护栏基准。现有多数工作只比 ASR。

**MVP**：统一接口接入 Guardrails AI / NeMo / LLM Guard / Llama Guard，跑同一攻击集与正常集，发布对比表与复现脚本。

**亮点**：**测量类项目的引用率往往高于方法类**；工作量可控；对社区有用。

### 4.4 备选：策略即代码 + 可回滚动作

**MVP**：声明式策略 DSL（`deny tool=shell if not approved_by=human`），带 dry-run 与回滚；接入一个真实 Agent 框架。

**亮点**：工程实用性强；但需要先有 4.1/4.2 的场景来证明其价值。

### 4.5 组合打法（推荐）

```
4.3 测量基线  →  4.2 中间件（被 4.3 度量）  →  4.1 具身扩展（形成护城河）
```

先用**测量**建立可信度，再用**中间件**证明能打，最后用**具身**建立差异化。每一步都有可发布产出，且后一步复用前一步的数据与代码。

---

## 5. 不做的事（避免消耗）

- ❌ 不做通用内容审核模型（卷、无差异化、需要大量标注）；
- ❌ 不追"越狱提示词大全"（速朽，且没有护城河）；
- ❌ 不做"用 LLM 判断 LLM 是否安全"的纯 prompt 方案（可被同样方式绕过，且延迟/成本高）；
- ❌ 不碰需要真实攻击他人系统的红队工作（合规风险）。
