## 摘要（Executive Summary）

1. **ROS 2 已是现代机器人软件开发的事实标准，而 DDS 与 Zenoh 构成其分布式通信的核心基础设施**；这一判断来自 2026 年一份 ROS 2 中间件架构综述 [35]。该文同时指出，这类中间件在动态、资源受限的无线环境下仍存在**结构性限制（structural limitations）** [35]。
2. **中间件抽象是有代价的，且代价可被量化。** 一项 2025 年工作指出 ROS 2 依赖的 DDS 提供 **20 条以上 QoS 策略**，但用户缺少安全策略组合与部署前验证的指南，导致试错调参与运行期意外失效；该文按 Discovery / Data Exchange / Disassociation 三阶段解释 **16 条 QoS 策略**，并推导出 **41 条依赖违规规则** [10]。
3. **实时性是 ROS 2 近年的活跃研究面。** 已有 ROS 2 实时性支持与分析的系统综述 [8]，以及针对商品化组件式实时系统（ROS 2 on Linux）的「中间件透明回调强制（middleware-transparent callback enforcement）」研究 [9]；MCU 侧的经典线索是 micro-ROS 的预算式实时执行器 [4]。
4. **中间件横向对比研究已有可核查的一手来源**：面向车载/自动驾驶场景的 FastDDS / Zenoh / vSomeIP 对比 [36]、ROS 2-DDS 实现面向协同驾驶的性能评估 [19]，以及更早的 Zenoh / MQTT / Kafka / DDS 吞吐与时延研究 [37]。但**这些来源的实验数字未在本次候选块中给出**，故本报告只陈述其研究对象与比较维度，不复述任何数值。
5. **工程栈层（ros2_control / Nav2 / MoveIt2）与发行版节奏存在严重证据缺口。** 候选池中**没有任何一条**覆盖 ROS 2 发行版命名与发布周期、RMW 抽象层演进、ros2_control 硬件接口、MoveIt2 规划管线、DDS Security 或 rosbag2 格式。
6. **仿真与多机器人侧的可用证据集中在具体技术栈与仿真器**：HuNavSim（ROS 2 人类感知导航仿真基准）[57]、Robotino 的 ROS 2 导航与仿真栈 [58]、gym-gazebo2（ROS 2 + Gazebo 强化学习工具链）[59]、Mini bot 3D（基于 ROS 的 Gazebo 仿真）[56]，以及把 ROS 2 与航天动力学框架 Basilisk 桥接的工作 [46]。
7. **总体结论**：以现有证据强度，本报告只能对「**中间件层**」给出中等置信度的结论；对「**工程栈层**」与「**发行版与安全层**」只能给出缺口清单。后续必须按 `ROS 2 Jazzy/Kilted/Rolling release`、`rmw_cyclonedds vs rmw_fastrtps benchmark`、`zenoh-bridge-ros2dds`、`MoveIt2 planning pipeline` 等精确查询重新检索。

## 二、中间件与实时性（DDS / RMW / Executor）

### 2.1 DDS 作为中间件抽象：理由与代价

**收益侧**：ROS 2 通过中间件抽象把通信语义下沉为可替换实现，DDS 与 Zenoh 因此可作为同一分布式通信基础设施的不同实现并存 [35]。

**代价侧（可量化）**：

- DDS 提供 **20 条以上 QoS 策略**，覆盖可用性、可靠性与资源占用；ROS 2 用户缺乏安全策略组合与部署前验证的明确指南，常导致试错调参与运行期失效 [10]。
- 该文按 **Discovery / Data Exchange / Disassociation** 三阶段解释 **16 条 QoS 策略**的作用方式，并推导出 **41 条依赖违规规则**，支撑静态验证 [10]。
- **术语纪律提醒**：[10] 中的 "life cycle" 指 **DDS 发布-订阅通信生命周期**，与 ROS 2 的 **lifecycle node（托管节点）机制无关**，二者不可混同 [10]。
- 综述层面指出，中间件在**动态且资源受限的无线环境**下存在结构性限制 [35]。此为综述作者主张，缺少独立第三方复现，> 待核实。

### 2.2 Executor、回调组与嵌套调度

- ROS 2 的实时调度可被形式化为**嵌套调度**：OS 线程调度 + 中间件层调度（ROS 2 Executor）；两者之间持续的一对一对应关系会带来约束问题 [9]。
- 已有专门的 ROS 2 实时性支持与分析综述，可作为该子领域的入口文献 [8]。
- micro-ROS 侧的经典工作提出**预算式（budget-based）实时执行器**，面向 MCU 受限算力 [4]。
- 候选池**未覆盖**：单线程 vs 多线程执行器 API 现状、MutuallyExclusive / Reentrant 回调组语义、executor 版本间行为变更。> 待核实。

## 三、控制与导航（ros2_control / Nav2 / MoveIt2）

### 3.1 结论先行：本章为最大证据缺口

候选池中**没有任何一条来源**以 ros2_control 的硬件接口（hardware_interface）、controller_manager 实时回路、Nav2 行为树（behavior tree）导航、或 MoveIt2 运动规划管线为研究对象。因此本章只能给出：(a) 缺口清单；(b) 方法论上相邻但**不可直接等同**的来源。

> 待核实：ros2_control 的 `SystemInterface` / `ActuatorInterface` / `SensorInterface` 设计与实时性保证；controller_manager 的 `update()` 周期与 realtime_tools 的锁策略；Nav2 的 BT navigator、controller/planner server 生命周期；MoveIt2 的规划管线（planning pipeline）、`moveit_cpp`、Servo 与 ros2_control 的耦合方式。以上均需以官方文档与仓库源码为依据重新检索。

### 3.2 方法论相邻来源（不可直接等同为 Nav2/ros2_control 证据）

- **采样型控制与安全约束**：BR-MPPI 将类 CBF 条件融入 MPPI 控制采样，用于强制多重不等式约束，并借助学习的符号距离场（signed distance fields）[71]。
- **非结构化环境反应式导航**：DRPA-MPPI 提出动态排斥势场增强的 MPPI [73]。
- **动态环境实时运动规划**：预测复合符号距离场（predicted composite signed-distance fields）用于动态环境实时规划 [74]。
- **导航栈与仿真集成**：Robotino 的 ROS 2 导航与仿真栈 [58]；HuNavSim 作为 ROS 2 人类感知导航的仿真基准 [57]。

> 待核实：上述算法是否已被 Nav2 的 MPPI controller 或 MoveIt2 采纳，以及集成的具体版本。**候选块未提供任何 Ros2/Nav2 集成的直接证据**，不得据此声称「Nav2 已支持 BR-MPPI」。

### 3.3 与工程栈直接相关的可用证据：节点组合（composition）

### 5.1 DDS 与 Zenoh 的路线分歧：证据现状

### 6.2 关键缺口：VLA 与 ROS 2 的**实际集成**几无证据

- 上述工作 [27][28][29][30][81] **均未在候选块中显示与 ROS 2 的集成关系**。任何「VLA 通过 ROS 2 topic/action 下发控制指令」「推理节点作为 rclpy 组件」「推理频率与 controller_manager 周期对齐」等论断，**在本报告证据基础上必须标注**：> 待核实。
- 唯一可确证的「非机器学习策略 + ROS 2 桥接」案例是 Basilisk × ROS 2 [46]，其控制器为**非线性模型预测控制（NMPC）**，并非学习型策略 [46]。可作为「ROS 2 被用作自主系统模块化接口」的旁证，但不可扩展为学习型策略集成证据。
- 方法论上值得注意的是 **sim-to-real 评估纪律** [33]：在把学习型策略接入 ROS 2 部署前，仿真结果的可外推性需要独立评估。

> 待核实：是否有把 VLA 推理封装为 ROS 2 节点/组件的开源实现；推理延迟是否满足 ros2_control 控制周期；VLA 输出（动作块/轨迹）到 `JointTrajectoryController` 的接口约定。
