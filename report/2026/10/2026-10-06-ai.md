## 摘要（Executive Summary）

1. **后训练范式已经完成从「RLHF/DPO 偏好对齐」到「RLVR + 推理型 RL」的叙事迁移**，多篇 2025 年综述与生命周期研究将其作为主线 [63][65][105]。但 2025–2026 年出现了来自独立研究的**系统性反证**：一项关于 pass@k 反转（Pass@k Inversion）的工作指出 RLVR 争议中有五个未被言明的前提，crossover 本身并不承载论文常宣称的结论 [56]；另一项预注册干预研究直接论证 RLVR 的增益**不可分解**（Does Not Decompose）[62]。也就是说，「RL 显著提升推理」这一命题的**效应拆解**仍处于未定论状态。
2. **Agent 评测的可信度危机已经是一手证据级的事实，而非社区传言**：静态 SWE-bench 家族被指出存在关键局限并催生 live 版本 [17]；SWE-ABS 通过对抗式加难证明 SWE-Bench Verified 榜首系统 78.80% 的成绩被高估，top-30 agent 中约**五分之一**「已解决」补丁在语义上是错误的，仅因测试套件太弱而通过 [24]；另有审计研究逐维度阅读 12 篇知名 agent benchmark 论文，指出「同 benchmark、同模型名、结果互相矛盾」是可复现性披露不足导致的常态 [5]。
3. **MoE 已经从「架构选择」变成「默认配方」**（Gemini-1.5、DeepSeek-V3、Llama-4 被同一篇论文作为采用 MoE 的代表 [81]），研究重心相应从「如何稀疏化」转向**部署侧效率**（专家剪枝 [71][73]、预测式专家缓存 [72]）与**适用条件分析**（视觉 MoE 何时才真正受益 [79]、路由的任务条件化签名 [80]）。数据受限预训练与 MoE upcycling 的扩展律也已有新结论 [85][88]。
4. **长上下文与推理效率已形成独立且拥挤的赛道**：KV cache 压缩/驱逐 [33][34][35][36][37][38]、扩散 LLM 的 KV 注意力改造 [32]、投机解码的工程化与场景化 [39][43][44][45]、多 agent 共享压缩 KV 池 [31]、dLLM 稀疏注意力 [29]。**但候选证据绝大多数只有摘要级信息，缺少真实的显存/延迟/吞吐实测数字**，因此本节的量化结论一律标注 `> 待核实`。
5. **多模态正走向「统一理解与生成（unified understanding & generation）」**，并同期出现综述骨架 [120] 与统一评测尝试 [119]，代表系统包括 Pisces [121]、Show-o2 [122]、PixelBytes [118]；同时基础模型的**透明度治理**已有年度量化报告 [90]。
6. **基础模型能力正在外溢到具身/驾驶**：VLA-Thinker 试图用「以图像思考（thinking-with-image）」增强 VLA [128]，驾驶 VLA 上出现推理时注意力引导 [129]——这属于本主题与具身智能的直接接口，但均为预印本级证据。

## 二、推理与测试时计算（Reasoning & Test-Time Compute）

### 2.1 主要进展

- **测试时计算被提升为「方法论变量」而非调参旋钮**：医学 LLM 研究领域已有独立论文论证 test-time compute 与 budget（即所谓 "Reasoning Effort"）是被低估的方法学变量，会实质影响结论可比性 [101]。这是把 TTS 从「工程技巧」上升到「实验设计合规性」层面的信号。
- **可证明的测试时计算扩展律**：已有工作尝试为 LLM 的 test-time compute 给出**可证明的 scaling laws** [103]，属于从经验曲线到理论刻画的一步。
- **RL 与测试时推理的贯通视角**：一篇 2025 综述以「从数据生成到测试时推理」为主线组织 LLM 中的 RL [105]，说明 TTS 与后训练在后验视角下被视为同一优化问题的两端。
- **TTS 外溢到生成模型**：面向 flow models 的推理时扩展（随机生成 + rollover budget forcing）出现 [97]，表明 test-time scaling 已不局限于自回归 LLM。
- **负面/边界证据（重要）**：RL 微调后，LLM 在**非理想条件下的推理能力**会被重新检验，该工作显示多数现有 benchmark 对非理想条件覆盖不足，RL 微调后的表现并非单调提升 [95]。
- **安全—技能权衡**：已有工作专门评估测试时计算约束对「安全性」与「技能」的双重影响 [106]，提示 TTS 并非纯收益。
- **争议核心**：pass@k 反转问题被系统化提出，作者认为 RLVR 辩论中存在五个未被言明的前提，**crossover 本身不足以承载常见结论** [56]。

## 三、后训练：RLHF / RLVR / 偏好优化

### 3.1 范式演进

- **骨架性综述**：《LLM Post-Training: A Deep Dive into Reasoning Large Language Models》提供了从 SFT → 偏好优化 → RL 的完整后训练地图 [63]；另有覆盖 LLM 全生命周期的 RL 综述 [65] 与「从数据生成到测试时推理」的 RL 综述 [105]。三篇可互为交叉验证，但**均为预印本级**。
- **RLHF 的理论化**：KL 约束下的迭代偏好学习（Iterative Preference Learning from Human Feedback）为 RLHF 提供理论—实践桥梁 [61]，属于本方向少数有形式化分析的条目。
- **算法层新增**：GVPO++（Group Variance Policy Optimization）面向后训练与 on-policy 蒸馏，尝试对组方差做策略优化改造 [67]。
- **RLVR 的域扩张**（2025–2026 的显著趋势）：可验证奖励机制被搬离数学/代码，进入
  - 化学环境基准（Molecular Pinball，确定性化学环境用于 RLVR benchmarking）[57]；
  - 流程建模（RLVR + universal rewards）[58][60]（注意：同一工作的两个不同仓储版本）；
  - 谈判（多买方市场中的 RLVR 谈判）[59]；
  - 世界模型（RLVR-World，用 RL 而非 MLE 训练世界模型以对齐任务目标）[48]；
  - 医学多模态幻觉（MC-R1，基于字符串匹配的可验证奖励缓解模态冲突幻觉）[50]。
- **不可验证数据上的 RL 扩展**：Beyond Verifiable Rewards 尝试把 RL 从可验证数据扩展到**不可验证数据** [64]，以及「从可验证奖励到自主演化」的路线论述 [66]。
- **失败模式与争议（关键）**：
  - **pass@k 反转**：`crossover` 现象不足以支撑 RLVR 的常见论断，作者列出五个未言明前提 [56]。
  - **增益不可分解**：一项**预注册干预研究**论证 RLVR 的收益无法被干净地分解归因 [62]——预注册设计使其方法学强度高于一般预印本。
  - 后训练—非理想条件的泛化退化 [95]（见第二节）。
- **长度偏置、reward hacking**：候选证据中**未检索到**针对长度偏置（length bias）或 reward hacking 的专门一手实验论文。`> 待核实`

## 四、Agent、工具使用与评测

### 4.1 工具使用与工具检索

- **工具检索是一个被低估的瓶颈**：Retrieval Models Aren't Tool-Savvy 专门为 LLM 工具检索建立 benchmark，指出通用检索模型在工具检索上能力不足 [2]。
- **小模型是弱工具学习者**：该工作以 multi-LLM agent 架构作为改进路径，说明「单一小模型直接学工具调用」的能力上限有限 [4]。
- **工具选择的权限安全**：Over-Privileged Tool Selection 研究 agent 在**不同权限等级的工具**之间的选择偏差，填补了此前只关注安全无关元数据的空白 [3]。
- **工具/agent 检索的图结构化**：Agent-as-a-Graph 以知识图谱做工具与 agent 检索 [21]；企业级编排框架 Z-SPACE 提供工具编排的工程范式 [13]。

### 4.2 评测可信度（本主题最强的一手证据簇）

- **披露不足导致不可复现**：一项审计逐维度阅读 12 篇知名 LLM agent benchmark 论文，动机正是「两篇论文在同一 benchmark、同一模型名下给出互相矛盾的结果」[5]。
- **静态 → 动态**：SWE-bench Goes Live 指出 SWE-bench 及其变体的关键局限并提出 live 版本 [17]（摘要截断，具体局限条目 `> 待核实`）。
- **对抗式加难揭示虚高**：SWE-ABS 报告 SWE-Bench Verified 榜首 78.80%，但 top-30 agent 的「已解决」补丁中约**五分之一在语义上错误**，仅因测试套件弱而通过 [24]。这是对**整个 test-based benchmark 范式**的普适性警告。

### 4.3 多 agent 系统与应用

- **污染传播**：多 agent LLM 系统中的错误/污染传播被形式化为可测量框架与基准 [12]。
- **协调能力基准**：LLM 驱动的多 agent 控制有专门框架与 benchmark [18]。
- **应用落地证据（含热度数字）**：ASIC-Agent 是带 benchmark 评估的 ASIC 设计多 agent 系统（citations=5，会议 ICLAD 2025）[11]；面向 arXiv 的 LLM 微调学术助手（citations=0，会议 ICRISET 2025）[10]。

### 5.2 MoE 架构

- **架构与训练综述**：MoE in LLMs: A Survey of Architecture, Training, and Efficient Inference 有两个仓储登记版本 [84][86]（同一工作），可作为骨架。
- **产业采用事实**：MoE 已被 Gemini-1.5、DeepSeek-V3、Llama-4 采用，但学术研究者**仍缺乏完全开放、端到端可研究的 MoE 平台**，FLAME-MoE 即为此缺口提出 [81]。
- **部署效率**：FlexMoE 提出「一对一嵌套的专家内部剪枝」，针对稀疏激活**不能消除全部专家存储与服务负担**的现实 [71]；Not All Experts are Equal 做专家剪枝与跳过的早期系统化工作 [73]；ExpertFlow 以**预测式专家缓存 + token 调度**优化 MoE 推理 [72]。
- **条件性结论（重要）**：视觉 MoE 的收益并非无条件——该工作在硬容量约束下研究 top-k 稀疏路由，指出实践部署受**专家坍缩（expert collapse）**与端到端效率增益有限所阻碍 [79]。这是对「MoE = 免费效率」的明确修正。
- **机制理解**：Task-Conditioned Routing Signatures 提出用「路由签名」向量刻画专家选择，指出路由机制此前理解不足 [80]。
- **理论**：Softmax Gating MoE 的收敛率分析 [76]；MoE 的历史性综述 [75]（2018，经典）；GraphMETRO 以对齐专家混合处理图分布偏移 [74]（与本主题相关度较低）。

### 5.4 长上下文与推理效率

**KV cache 压缩/驱逐**
- 驱逐类：Make Each Token Count [33]、ReST-KV（逐层输出重建 + 时空平滑）[36]。
- 压缩率维度：KV-Compress（按 attention head 变压缩率的分页压缩）[35]、Attention-Weighted Value Projection [34]。
- 预测类：AttentionPredictor（时序模式）[37]、Expected Attention（从未来 query 分布估计注意力）[38]。
- 扩散 LLM 专用：Attention Is All You Need for KV Cache in Diffusion LLMs [32]。
- **多 agent 场景**：PolyKV 用**非对称压缩**的共享 KV 池（Keys 按 int8/q8_0 量化）替代每 agent 独立 KV，并通过 HuggingFace DynamicCache 注入 N 个上下文 [31]。**摘要在 Values 压缩方式与显存/吞吐数字上均未给出。`> 待核实`**

**注意力替代（长上下文）**
- dLLM 长上下文推理：Focus-dLLM 以**置信度引导上下文聚焦** + 稀疏注意力替代双向全注意力；作者明确指出难点在于**为尚未解码的 token 估计注意力重要性** [29]。摘要**未给出加速比/显存数字** `> 待核实`。
- **上下文选择作为长窗口替代**：LTG 在 SemEval-2025 Task 10 子任务 1 中用简单的实体启发式做上下文选择，使有限窗口模型（XLM-RoBERTa）达到与**更大生成式模型 SFT 持平或更优**的效果 [28]。这是「不扩窗、改选料」的低成本路线。

## 七、争议与开放问题

### 7.1 RLVR 的收益是否可归因、是否可分解
- **争议点**：RLVR（可验证奖励强化学习）在数学/代码上的增益被广泛宣传，但 [56] 指出 pass@k 存在「反转（inversion）」现象，并列出 RLVR 讨论中常被略去的五个前提；[62] 以预注册干预研究（pre-registered intervention study）直接论证「RLVR 的增益不可分解」。
- **四轴**：热度 `> 待核实`（候选块无引用数/榜单信号）[56][62]；权威为 Zenodo 预印本与 SSRN 预印本，同行评审状态 `> 待核实` [56][62]；关注度中（属对既有 SOTA 叙事的直接反驳，是当前评测争议的核心之一）[56][62]；推荐度 ★★★★☆——在引用任何 RLVR 提升数字前应先读这两条反证 [56][62]。
- **配套证据**：[95] 显示 RL 微调后模型在**非理想条件**（噪声/干扰）下的推理能力表现受限，提示标准基准可能高估稳健性；热度 `> 待核实`，权威为 arXiv 预印本（cs.AI），关注度低—中（候选块无引用信号），推荐度 ★★★★☆ [95]。
- **开放问题**：RLVR 增益究竟来自「推理链合法性的可验证性」还是「输出分布收窄/长度变化」，候选证据尚未给出统一归因框架 `> 待核实` [56][62][63]。

### 7.2 长度偏置、reward hacking 与不可验证域的扩展
- [64] 明确指向「把 RL 从可验证域扩展到不可验证数据」这一瓶颈，标题本身即为对「可验证奖励」必要性的挑战；热度 `> 待核实`，权威为会议/论文集 DOI 指向的出版物（同行评审状态 `> 待核实`），关注度中，推荐度 ★★★★☆ [64]。
- [63] 作为后训练深潜综述覆盖「推理型 LLM 的后训练」全貌，可用于核对长度偏置与失败模式是否有系统整理；热度 `> 待核实`，权威为 arXiv 预印本（arXiv:2502.21321v2），关注度中—高（综述类被广泛引用，但具体引用数 `> 待核实`），推荐度 ★★★★☆ [63]。
- [50] 在**模态冲突**场景下用基于字符串匹配的可验证奖励抑制幻觉（MC-R1），说明「可验证奖励」正被外推到多模态，但此类外推的有效性 `> 待核实`；热度 `> 待核实`，权威为 IEEE TMM 关联材料（DOI 指向），关注度低—中，推荐度 ★★★☆☆ [50]。
- 尚未见统一的 **reward hacking 度量标准**：候选证据中 [57][58][59][60][66] 分别在不同领域（化学环境、过程建模、谈判）做 RLVR 特化，缺乏横向可比口径，`> 待核实`。

### 7.3 测试时计算作为「被忽视的方法学变量」
- [101] 直接把「测试时计算与预算（reasoning effort）」定义为医疗 LLM 研究中**被低估的方法学变量**；[106] 则评测测试时计算约束对**安全与技能**的影响。二者共同提示：不同论文报告的推理成绩可能因测试时预算不同而不可比。
- **四轴**：热度 `> 待核实` [101][106]；权威为期刊论文（[101]，DOI 指向 Korean Journal of Radiology 系刊，同行评审）与 ACM 会议论文（[106]），属本章中权威较高的两条；关注度中（方法学批评类，非高热度话题）；推荐度 ★★★★☆——做跨论文成绩对比时必读 [101][106]。
- [103] 提出「测试时计算的可证明扩展律」，与经验性 scaling 形成理论与实证的张力；热度 `> 待核实`，权威为论文集 DOI 出版物（同行评审状态 `> 待核实`），关注度中，推荐度 ★★★★☆ [103]。
- [97] 把推理时扩展（随机生成 + rollover budget forcing）推广到**流模型**（非自回归生成），说明测试时计算范式正外溢到扩散/流式生成；热度 `> 待核实`，权威为 arXiv 预印本，关注度低—中，推荐度 ★★★☆☆ [97]。

### 7.4 Agent 评测的可信度危机
- 三条互相印证的争议证据：[24] 报告 SWE-Bench Verified 榜首 78.80% 的成功率被**高估**，top-30 agent 中约五分之一「已解决」补丁语义错误，仅因测试套件太弱而通过；[17] 指出原基准缺少实时更新与抗污染能力；[5] 审计 12 篇知名 agent 基准论文，发现同一基准、同一模型名却结论互相矛盾。
- **四轴**：热度 `> 待核实` [5][17][24]；权威均为 arXiv 预印本（cs.SE / cs.LG），同行评审状态 `> 待核实`；关注度中—高（直接挑战已被广泛引用的 SWE-bench 数字）；推荐度 ★★★★★（[24]）、★★★★☆（[17][5]）。
- 工具层的不确定性：[2] 显示检索模型在**工具检索**上能力不足，[3] 发现 agent 在**权限敏感**的工具选择上存在越权倾向，[4] 指出小模型是「弱工具学习者」（需多 LLM 协作）。三条均为 arXiv 预印本（[2] v2、[3] v2、[4] v3），热度 `> 待核实`，关注度低—中，推荐度 ★★★★☆（[2][3]）、★★★☆☆（[4]）。
- 多智能体系统的新风险：[12] 提出多 agent LLM 系统中「污染渗流（contamination percolation）」的测量框架与基准；热度 `> 待核实`，权威为预印平台 DOI 材料（同行评审状态 `> 待核实`），关注度低—中，推荐度 ★★★☆☆ [12]。
- 明确的**失败模式缺口**：候选证据中缺少「长程任务失败分类学」的统一口径，各基准（[5][17][24]）披露维度不一致，`> 待核实`。

### 7.5 多模态「统一理解与生成」的评测稳健性
- [120] 是对统一多模态理解-生成模型的综述，明确列出挑战与机会；[119] 提出整体评测口径；[121]（Pisces，自回归统一基础模型）与 [122]（Show-o2，原生统一模型）代表两条实现路线；[118]（PixelBytes）探索统一嵌入。
