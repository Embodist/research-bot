## 4. 瓶颈与拐点

### 4.1 核心瓶颈
| 瓶颈 | 表现 | 证据 | 严重度 |
|------|------|------|--------|
| **弱监督信号质量上限** | 弱模型/人类标注噪声、偏好冲突、覆盖率不足，限制强模型对齐上限 | [3, 11, 12] | ⭐⭐⭐⭐⭐ |
| **可扩展监督形式化缺失** | Debate 与 RLAIF 长期割裂，缺乏统一收敛/最优性分析 | [31] | ⭐⭐⭐⭐ |
| **长上下文对齐工程墙** | 序列并行、内存优化、损失计算稳定性在 100k+ 上下文仍是痛点 | [14] | ⭐⭐⭐⭐ |
| **奖励模型校准与不确定性缺位** | 奖励分数不可校准、分布外过度自信、无标准不确定性输出接口 | q3 open_problems, [13, 15] (非 LLM 领域) | ⭐⭐⭐⭐ |
| **评测基准滞后于方法** | 现有基准 (HH-RLHF, MT-Bench 等) 无法区分可扩展监督方法优劣，缺乏动态/对抗/长程基准 | [10] (透明度指数侧写) | ⭐⭐⭐ |

### 7.3 核心不确定性与风险
- **U1 弱到强理论极限**：若强模型能力远超弱监督信号表达上限，集成/辩论/过程监督均失效 → **超对齐路线图受阻** [3, 11]。
- **U2 奖励模型对抗脆弱性**：高分奖励模型易被策略攻击，校准与不确定性若不解决，**RLHF 训练不稳定/奖励作弊** 风险持续 [33, q3 open_problems]。
- **U3 评测作弊与 Goodhart 定律**：基准榜单 (Arena, MT-Bench) 与真实部署偏好相关性下降，**榜单 SOTA ≠ 产品 SOTA** [10]。
- **U4 算力获取不确定性**：出口管制、能源瓶颈可能限制大规模对齐实验，**工程验证周期拉长** `> 待核实`。
