# 证据分级（Evidence Grading）

## 分级标准
| 等级 | 证据类型 | 可信度 |
|------|----------|--------|
| A | 同行评审论文（RSS/CoRL/ICRA/NeurIPS…）、官方技术报告 | 高 |
| B | arXiv 预印本、官方 GitHub 仓库、官方数据集主页、厂商官方博客 | 中高 |
| C | 第三方复现、基准榜单、权威媒体深度报道 | 中 |
| D | 个人博客、社区帖子、聚合站、二手翻译 | 低 |
| E | 无法访问/内容为空/仅标题 | 不可用 |

## 冲突处理
1. 两个来源矛盾时，优先采信等级更高者，并在正文注明分歧
2. 数字类结论必须以一手表格/榜单为准，不用二手转述
3. 时间敏感结论（SOTA、版本号）以最新官方来源为准

## 表述纪律
- A/B 级证据 → 可直接陈述
- C 级证据 → 加限定词「据报道 / 第三方评测显示」
- D 级证据 → 仅作线索，必须另找高等级来源，否则标注 `> 待核实`
- E 级证据 → 丢弃

## 四条证据轴（每条关键条目/结论都要有）
除等级外，每条关键条目/结论必须给出四类可核查证据：

- **热度证据（heat）**：引用数 citations、GitHub star、下载量、榜单排名。来自候选块的
  `citations=`/`stars=` 等字段；取不到就写 `> 待核实`，**不得编造数字**。
- **权威证据（authority）**：发表 venue、是否同行评审、官方文档/标准、维护机构与作者。用于判断该结论
  是"学术共识"还是"厂商宣传"。
- **关注度（attention）**：`高 | 中 | 低` 并给一句依据（引用数/star/下载/榜单排名/新闻或社区讨论热度）。
  关注度是对"社区当下关注程度"的判断，比单纯的 heat 数字更进一步，但依据仍须来自真实信号。
- **推荐度（recommendation）**：`★1-5`，附一句话推荐理由，综合 **权威 + 热度 + 关注度 + 与本主题的相关性**。
  这是"值不值得读/用"的编辑判断：顶会且有热度 → 高；来源不可核实 → 低。

四条轴要一起看：高 star 的仓库不等于已同行评审；顶会论文也可能尚无引用。每条都要带 [n] 引用。

## 每条发现应携带的元数据
`point`、`evidence`、`sources`(引用编号)、`type`、`confidence`、`year`、`heat`、`authority`、`attention`、`recommendation`
confidence 与证据等级对应，不得夸大。
